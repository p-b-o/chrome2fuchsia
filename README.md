# Chrome2Fuchsia

> **This program was fully generated by [Claude](https://claude.ai) (Anthropic) through an iterative conversation — including the implementation, bug fixes, optimisations, and this README. No human-written code was involved.**

Convert a [Chrome Trace Event Format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU) (JSON) trace to [Fuchsia Trace Format](https://fuchsia.dev/fuchsia-src/reference/tracing/trace-format) (FXT) binary, suitable for loading in [Perfetto](https://ui.perfetto.dev).

Reads from **stdin**, writes binary FXT to **stdout**.

---

## Building

You need [yyjson](https://github.com/ibireme/yyjson).

```sh
cc -O2 -o c2f c2f.c -lyyjson -lm
```

---

## Usage

```
c2f [OPTIONS] < input.json > output.fxt
```

| Option | Description |
|---|---|
| `--help`, `-h` | Show help and exit. |
| `--verbose` | Print conversion statistics to stderr when done. |
| `--progress` | Show an animated progress bar on stderr during conversion. |

### Examples

```sh
# Basic conversion
./c2f < trace.json > trace.fxt

# Show statistics after conversion
./c2f --verbose < trace.json > trace.fxt

# Show progress bar while converting a large trace
./c2f --progress < trace.json > trace.fxt

# Both flags together
./c2f --verbose --progress < trace.json > trace.fxt

```

### Viewing the result

Open [ui.perfetto.dev](https://ui.perfetto.dev) and drag and drop the `.fxt` file.

## What it does

### Input format

Chrome (and Chromium-based tools) export traces as JSON in the [Trace Event Format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU). The root may be either:

- An object with a `traceEvents` array: `{ "traceEvents": [ ... ] }`
- A bare array: `[ ... ]`

### Supported Chrome event phases

| Phase | Name | FXT equivalent |
|---|---|---|
| `B` | Duration begin | Duration begin event |
| `E` | Duration end | Duration end event |
| `X` | Duration complete | Duration complete event |
| `i` / `I` | Instant | Instant event |
| `C` | Counter | Counter event |
| `b` | Async begin | Async begin event |
| `n` | Async instant | Async instant event |
| `e` | Async end | Async end event |
| `s` | Flow begin | Flow begin event |
| `t` | Flow step | Flow step event |
| `f` | Flow end | Flow end event |
| `M` | Metadata | Used for process/thread names (not emitted as an event) |

All other phase types are emitted as instant events so the event count is preserved.

### Process and thread names

Chrome `M` (metadata) events with `name` equal to `process_name` or `thread_name` are used to populate Fuchsia [Kernel Object Records](https://fuchsia.dev/fuchsia-src/reference/tracing/trace-format#kernel-object-record) for each process and thread. These records are what Perfetto uses to display named timeline rows.

```json
{"ph": "M", "name": "process_name", "pid": 1, "args": {"name": "MyApp"}}
{"ph": "M", "name": "thread_name",  "pid": 1, "tid": 2, "args": {"name": "MainThread"}}
```

`M` events are collected in a dedicated pre-pass before any FXT records are emitted, so they work correctly regardless of where in the array they appear. If no `M` event exists for a given pid or tid, the numeric value is used as a fallback name.

### Argument types

JSON argument values are mapped to FXT argument types:

| JSON type | FXT argument type |
|---|---|
| Unsigned integer | `uint64` (type 4) |
| Signed integer | `int64` (type 3) |
| Floating-point | `double` (type 5) |
| String | `string` (type 6) |
| Boolean | `bool` (type 9) |
| Null / object / array | `null` (type 0) |

### `args.srcline` argument

The `args.srcline` argument, if present, is passed through as-is as a single FXT string argument. Splitting it into separate `src` and `line` arguments would cost an extra 16 bytes per event due to the mandatory int64 value word, so the combined form is retained under the key `args.srcline`.

## Limitations

- Up to **32 767** unique strings in the string table. Beyond this, strings are encoded inline (larger but still correct).
- Up to **255** unique `(pid, tid)` pairs in the thread table. Beyond this, threads are encoded inline.
- Up to **15** arguments per event (FXT header field is 4 bits).
- Record size is limited to 8 KB per event by `MAX_RECORD_BYTES`; events with very long string arguments approaching this limit will be truncated.
- Timestamps are assumed to be in **microseconds** (the Chrome trace default) and are converted to nanoseconds for FXT (1 tick = 1 ns per the initialization record).
